## Anthropic / Claude updates
- **Status change on the CLI-hang issue**: [anthropics/claude-code#86074](https://github.com/anthropics/claude-code/issues/86074) ("`claude -p` has no API request timeout — black-holed TCP connection hangs headless run indefinitely") was "acknowledged, open" as of yesterday's scan. Live-checked today: **closed as not planned**. No fix is coming from Anthropic for this failure mode. `core/scorer.py`'s own `subprocess.run(..., timeout=600)` + retry-on-`TimeoutExpired` remains the only mitigation that exists — this is now confirmed, not just likely, to stay a self-maintained concern.
- Related and separately confirmed closed-not-planned: [anthropics/claude-code#28489](https://github.com/anthropics/claude-code/issues/28489), a feature request for built-in verify/retry/resume + standardized exit codes for `claude -p` automation. Same conclusion: Anthropic isn't building a native reliability wrapper for headless mode; hand-rolled retry logic (what scorer.py already has) is the durable pattern here, not a stopgap for a feature that's coming.
- The #86074 thread's own suggested workaround for faster stall detection: poll the subprocess's cumulative CPU time and kill/relaunch when it flatlines (a stalled CLI burns ~0 CPU; a live one burns it continuously). This would let a hang be detected well before the full 600s timeout elapses, rather than always waiting it out. Not proposing this as a change — flagging it as a cheaper-latency refinement worth knowing about if the 600s wait itself ever becomes the bottleneck (source: issue comment thread, not an official Anthropic doc).
- Official Claude Code changelog (`code.claude.com/docs/en/changelog`), September 2026 entries relevant to reliability: v2.1.261 fixed `/goal` runs silently stalling after API errors/network drops — now retries with backoff or pauses and explains why; v2.1.260 fixed the case where the API sends no response headers, extending the retry wait to the full 10-minute `API_TIMEOUT_MS` instead of cutting it short at 3 minutes. Neither directly touches one-shot `claude --print` invocations (they're `/goal`- and interactive-session-scoped), but both are Anthropic's own current retry/backoff vocabulary and roughly match the shape scorer.py already uses.

## Agent techniques / patterns
- No new pattern beyond what yesterday's scan already covered (circuit breaker → backoff retry → dead-letter queue as the standard unattended-pipeline shape, already reflected in this project's `health-check-is-presence-not-outcome` fix).
- **Self-play outcome-ranked fine-tuning** ([arxiv 2502.05253](https://arxiv.org/abs/2502.05253), "LLMs Can Teach Themselves to Better Predict the Future"): generates multiple independent reasoning traces + forecasts per question, ranks them post-hoc by distance to the actual outcome, and fine-tunes on the ranking via DPO — +7–10% accuracy on 14B open models. Not directly usable here (Claude via CLI isn't fine-tunable, and this is an offline training technique, not a runtime one), but the underlying idea — generate a few independent probability estimates per market and treat their *spread* as a self-critique/confidence signal at scoring time — is a lighter-weight, non-fine-tuning version of the same idea that would fit this project's existing single-call-per-market architecture without an ensemble-scale cost increase. Flagging the idea, not the paper's method, as the potentially relevant bit.
